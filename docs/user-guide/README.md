# sshs3 user documentation (source)

These Markdown files are the **single source** of the documentation published at <https://docs.sshs3.com>.
The site repo (`sshs3-site`) only holds the presentation: templates, the page registry and the build. Edit the
text here, in the same commit as the code it describes (see [CONTRIBUTING.md](../../CONTRIBUTING.md)).

## How it gets published

`scripts/deploy-site.sh` (run by `scripts/deploy.sh` when `docs/` changed, or on its own) rebuilds the site from
this checkout: `npm run build:docs` in `sshs3-site` reads these files, the IPC channels and keyboard shortcuts
(extracted from `src/shared/types/ipc.ts` and `settings.ts`) and renders them through the site templates.

- **One file = one page.** The page list, order, titles and summaries live in `sshs3-site/scripts/build-docs.js`
  (the `modules` registry). A new page needs a file here **and** an entry there. This README is not a page.
- **Screenshots** live in [`docs/screenshots/`](../screenshots) and are referenced as `/img/docs/<name>.png`
  (they are synced to the site on deploy; the references do not render when browsing the files on GitHub).
- **Generated blocks:** `{{AUTOGENERATED_SHORTCUTS_TABLE}}` and `{{AUTOGENERATED_IPC_TABLE}}` are replaced at build time.
- **Site syntax:** `<!-- tabs:… -->` / `<!-- tab:Title -->` for tabbed code, `> [!NOTE]` / `> [!IMPORTANT]` for callouts,
  and fenced `mermaid` blocks for diagrams. They degrade to plain Markdown elsewhere.
- **Language:** English only.

## Writing rules

- Describe what the app does today; verify button and setting names against the UI (`src/renderer`) and
  `src/shared/types/settings.ts`. Do not document settings or labels that do not exist.
- Use the exact UI labels in **bold** and keyboard shortcuts in `<kbd>`.
